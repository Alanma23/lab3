# How to Test Lab 3 (SIMD + Sobel)

## Requirements

- **iverilog** and **gtkwave** (for simulation)
- **MIPS toolchain** for building test programs: the Makefile expects it at  
  `sim/../tools/gcc-mips/mips_tc`  
  (i.e. `tools/gcc-mips/mips_tc` from the lab root).  
  On **FarmShare** this is set up; from home you may need to build it (see lab handout).

---

## 1. Test SIMD + ABS instructions only

From the **lab root** (`lab3/`):

```bash
cd sim
make test_simd_abs
```

This builds the `simd_abs` test (uses `.word` for PADD.B, PSUB.B, PSLL.B, PABS.B, PUNPKLO, PUNPKHI, ABS), runs the simulator, and reports pass/fail.

**If you see:** `mips-elf-gcc: No such file or directory`  
→ Build the toolchain first (see lab handout) or run on FarmShare.

---

## 2. Run all unit tests (including simd_abs)

```bash
cd sim
make test
```

Runs every test in `sim/tests/` (add, sub, simd_abs, etc.) and prints a summary.

---

## 3. Test the SIMD Sobel

The Sobel program lives in **`sim/sobel_asm/`**, but the test harness only runs tests under **`sim/tests/`**. So you need sobel_asm **inside** `tests/`:

```bash
cd sim
cp -r sobel_asm tests/sobel_asm
make test_sobel_asm
```

This will:

1. Build the simulator (Verilog) and the Sobel test program (sobel_mips.S + sobel_simd.S).
2. Run the sim with the test’s `test.conf` (cycles, image size, etc.), `ibuf.hex` (input image), and reference `obuf.hex`.
3. Compare the simulator’s output buffer to `obuf.hex` and write pass/fail to `tests/sobel_asm/test.result`.

**Note:** The reference `obuf.hex` in the handout is usually produced by the **scalar** Sobel. If you only have that reference, the SIMD Sobel should produce the same output (same math); if the test fails, the difference may be in edge/tail handling or you may need a reference generated by the SIMD build.

---

## 4. Debug a single test (e.g. simd_abs)

View the simulation waveform:

```bash
cd sim
make wave_simd_abs
```

(Requires **gtkwave**.)

---

## 5. Build simulator only (no toolchain)

To only check that the Verilog compiles (no test programs):

```bash
cd sim
rm -f build/userlogic_test
make build/userlogic_test
```

If this succeeds, your SIMD/ABS changes in `alu.v`, `decode.v`, and `mips_defines.v` are at least syntactically correct.

---

## Quick reference

| Goal                    | Command (from `sim/`)     |
|-------------------------|---------------------------|
| SIMD/ABS unit test      | `make test_simd_abs`      |
| All unit tests          | `make test`               |
| SIMD Sobel test         | Copy sobel_asm into tests, then `make test_sobel_asm` |
| Waveform for a test     | `make wave_<testname>`    |
| Build sim only          | `make build/userlogic_test` |
